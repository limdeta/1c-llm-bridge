# AGENT.md — правила работы агента (прочитай перед первым шагом)

Ты подключён к информационной базе 1С:Предприятие. Этот файл — свод правил работы;
детали — в документах, на которые он ссылается.

## Главное

1. **Ты работаешь строго в рамках прав своей роли в 1С.** Если чего-то не хватает —
   это вопрос к администратору и владельцу базы, а не задача «дойти любым способом».
2. **Ты не читаешь кодовую базу, ты рисуешь её карту.** Один шаг — один проверяемый
   факт с источником. Ограничения не обходятся, а обсуждаются.
3. **Крупная задача — это проект, а не шаг.** Если задача требует десятков шагов и
   данных, ты останавливаешься и говоришь об этом человеку до первого вызова.

## Порядок работы

1. Понять задачу и проверить её размер по гейту (`PLAYBOOK.md`, §2).
2. Если задача проходит гейт — определить точку входа и первый узел карты.
3. Сделать один шаг: одна операция с известными лимитами.
4. Записать факт в карту (`map/`), обновить статус узла.
5. Повторять, пока не достигнут критерий приёмки шага. Перед новым шагом — сверить карту,
   чтобы не читать уже прочитанное.

## Что можно

- Читать данные, метаданные и код в пределах своей роли и лимитов инструментов.
- Читать **структуру** модулей (перечень процедур), затем — **одну** процедуру по имени.
- Готовить изменения как текст (патчи, XML-исходники, спецификации), не применяя их.
- Вести карту и заметки: общее — в `PITFALLS.md`, про нашу среду — в
  `docs/company/STAND_NOTES.md`. Записывать грабли нужно сразу, а не «потом».

## Чего нельзя

- Писать в базу что угодно, включая «безобидные» пометки на удаление.
- Загружать конфигурацию, применять расширения, захватывать объекты в хранилище
  без явной команды человека.
- Вызывать код конфигурации (отчёты, обработки, HTTP-методы) без явной команды на вызов.
- Ходить в СУБД напрямую или просить доступ к ней.
- Читать модули целиком, выгружать конфигурацию «на всякий случай», запускать массовые
  обходы метаданных.
- Снимать настройки безопасности и пытаться обойти права или лимиты инструментов.

## Быстрые команды

```powershell
# Проверка готовности моста (делай первой)
powershell -NoProfile -File bridge\onec.ps1 -ConnectionString "$env:ONEC_CONNECTION_STRING" check

# Версии и конфигурация
powershell -NoProfile -File bridge\onec.ps1 info

# Запрос (на стенде заказчика — только через инструменты с лимитами, см. TOOLS.md)
powershell -NoProfile -File bridge\onec.ps1 query "ВЫБРАТЬ ПЕРВЫЕ 5 Наименование ИЗ Справочник.Товары"

# Метаданные (только имена объектов)
powershell -NoProfile -File bridge\onec.ps1 meta catalogs
```

Прямое выполнение кода (`exec`) на стенде заказчика **выключено**; в песочнице —
разрешено. Строка соединения берётся из `ONEC_CONNECTION_STRING` или параметра.

Если скрипты запрещены политикой, а exe разрешены — используй `bridge\bin_fd\onec.exe`.

## Удалённый режим (SSH)

Мост обязан работать на той машине, где стоит 1С; ты сам можешь быть на другой.
Если у тебя есть PowerShell (в том числе на своей стороне) — короткий путь:

```powershell
$env:ONEC_SSH = "<пользователь>@<машина-с-1С>"
$env:ONEC_REMOTE_BRIDGE = "C:\1c-bridge\bridge\onec.ps1"
$env:ONEC_CONNECTION_STRING = 'File="C:\Bases\МояБаза";Usr="Имя";Pwd=""'
powershell -NoProfile -File bridge\remote.ps1 check
```

Если PowerShell у тебя нет (Linux-харнес, bash-оболочка) — `tools/ssh_exec.py`,
зависимостей у него нет:

```bash
export ONEC_CONNECTION_STRING='Srvr="srv";Ref="база";Usr="имя";Pwd=""'
python3 tools/ssh_exec.py --target user@vm --bridge C:/1c-bridge/bridge/onec.ps1 query "ВЫБРАТЬ ПЕРВЫЕ 5 Наименование ИЗ Справочник.Товары"
```

Строку соединения передавай **через переменную окружения**, а не аргументом: PowerShell
искажает кавычки при передаче аргументов чужим программам (грабля № 47), а кириллицу в
аргументах ломает SSH-оболочка Windows (грабля № 48) — поэтому внутри всё идёт через
`-EncodedCommand` (base64 UTF-16).

## Если чего-то не хватает

**Не хватает прав или инструментов — говори об этом прямо и останавливайся.** Формулировка:
«Для выполнения задачи мне нужны такие-то права (или такой-то инструмент), сейчас их у меня
нет». Решение принимает администратор; самостоятельно искать обход — нарушение правил.
Мы идём самым безопасным путём: лучше невыполненная задача, чем лишний доступ.

| Симптом | Что сказать человеку |
|---|---|
| `check` → «Исполнитель недоступен» | «Примени расширение: `apply_extension.ps1 -InfoBasePath <путь>`» |
| «Идентификация пользователя не выполнена» | «Дай корректную строку соединения / проверь пользователя ИБ» |
| «Недостаточно прав» | «Для этой задачи нужны такие-то права — сейчас их нет» |
| Нужен объект вне выданной роли | «Мне нужен доступ на чтение к <объект>; если нельзя — предложу, как обойтись без него» |
| Нет нужного инструмента | «Нужна операция <что именно>; предлагаю добавить её отдельным согласованным шагом» |
| Серверная база | Строка вида `Srvr="server";Ref="ИмяБазы";Usr="...";Pwd="..."` |
| Задача больше похожа на проект | «Это N шагов и M модулей, предлагаю начать с …» (шаблон в `PLAYBOOK.md`, §2) |
