# Инструменты агента: что есть и что гарантируется

Файл описывает поверхность инструментов — то, **чем** агент дотягивается до 1С. Смысл
документа: каждое действие агента проходит через узкую операцию с известными лимитами,
а не через «выполнить любой код».

## Принцип: узкая операция вместо свободного кода

Свободное исполнение произвольного кода (`Выполнить(Код)`) — самая удобная и самая
опасная возможность: им одинаково легко прочитать одну запись и запустить цикл по
регистру с миллионами строк. Поэтому:

- на стенде заказчика свободный `exec` **не применяется** (в песочнице — можно);
- вместо него — набор параметризованных операций, каждая со своими лимитами;
- свободный `exec` остаётся только в нашей песочнице, где ломать нечего.

## Операции

| Операция | Что делает | Лимиты | Состояние |
|---|---|---|---|
| `check` | проверка готовности моста (платформа, подключение, исполнитель, запросы) | — | есть (`bridge/onec.ps1`, `bridge/bin_fd/onec.exe`, `bridge/onec.py`) |
| `info` | версия платформы, имя конфигурации | — | есть |
| `meta_list` | перечень объектов метаданных по виду (справочники, документы, регистры…) | только имена, без свойств | есть как `meta`, требует сужения |
| `objects_search` | поиск объекта по имени/синониму в метаданных | до 50 совпадений | план |
| `record_get` | одна запись справочника/документа по ссылке или реквизиту | 1 запись, до 64 КБ | план |
| `table_read` | чтение физической таблицы по фильтру | принудительный `ПЕРВЫЕ N`, обязательный период, до 200 строк | план |
| `query_capped` | запрос на языке запросов с проверками | без `*`, ≤4 источников, ≤200 строк, 15 с | частично (`query`), проверки — план |
| `module_outline` | перечень процедур/функций модуля с номерами строк | только подписи, без тел | план |
| `module_read` | тело одной процедуры по имени | 1 процедура, до 8000 символов | план |
| `code_invocation` | вызов кода конфигурации (отчёт, обработка, HTTP-метод) | требует явной команды человека на каждый вызов | план |
| `map_append` | запись факта в карту разведки | — | план |
| `budget_status` | сколько бюджета израсходовано | — | план |

Прикладных (бизнес-) инструментов в MCP-сервере нет: `bridge/mcp_server.py` отдаёт только
`info`, `execute`, `query`, `metadata`. Примеры прикладного слоя лежат в `sandbox/` — это
полигон для проверки моста, к работе с реальной конфигурацией он отношения не имеет.

## Как читать ответ

- `truncated: true` + `total_count` — данных больше, чем отдано. Это норма: агент видит
  масштаб, но не тянет объём в контекст. Сужать надо условием, а не увеличением лимита.
- Отказ инструмента — это результат шага, а не сбой: причина и подсказка возвращаются
  вместе с отказом.
- `budget_status` показывает остаток; при исчерпании операции отказывают до конца задачи.

## Правила вызова

1. Одна операция — одна цель. Если операция нужна «заодно ещё для трёх вещей» — это
   три отдельных шага.
2. Результат шага сразу уходит в карту (`map/`); в контексте остаётся выжимка.
3. Повторный вызов с теми же параметрами не делается — сначала проверяется карта.
4. Если операция вернула отказ — не переформулировать ради обхода, а сообщить человеку.
5. Перед «тяжёлой» операцией на стенде — сверить её с чек-листом шумных запросов
   в [`LIMITS.md`](LIMITS.md).

## Что слой инструментов гарантирует и что нет

**Гарантирует:** объём ответа, принудительный `ПЕРВЫЕ N`, обязательный период,
запрет `*`, число источников, отказ при исчерпании бюджета.

**Не гарантирует:** что серверный запрос прекратится после клиентского таймаута — нет;
что неполный анализ не будет выглядеть полным — нет (это метод, см. `PLAYBOOK.md`);
что роль в 1С настроена верно — это отдельный слой, он описывается во внутренних
документах о доступе.

## Как добавляется новая операция

1. Сначала на полигоне (`sandbox/`): собрать, проверить, понять реальное время работы.
2. Понять, какой объём данных операция может задеть, и дописать её в таблицу выше.
3. Проверить, что операция **не даёт** обойти проверки (например, не принимает
   произвольный текст запроса без валидации).
4. Только потом — на стенд заказчика, как отдельное согласованное изменение.
