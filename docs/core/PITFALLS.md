# Грабли: ядро (платформа, COM, PowerShell, запросы)

Общая часть базы знаний: грабли, воспроизводимые на любой машине, любой базе и любой конфигурации — платформа и COM, язык запросов и регистры, PowerShell/Python, расширения конфигурации, приёмы работы с репозиторием.
Сюда пишем только то, что можно отдать любому 1С-программисту: сведений о конкретной площадке (заказчик, его стенд, адреса, права, процессы) здесь быть не должно — они ведутся отдельно от общей части.
Нумерация записей сохранена от прежнего единого списка грабель; сюда попадают общие записи, записи о конкретной среде лежат в разделе про неё.
Новую граблю пишем сразу сюда, если она общая; если она про нашу среду — в заметки о среде.

## COM (V83.COMConnector)

### 1. COMConnector не зарегистрирован (0x80040154, Class not registered)
Установка платформы НЕ регистрирует `V83.COMConnector` (для HKLM нужен админ).
**Решение:** регистрация в HKCU без админа — `bridge/setup_com.ps1`:
- `HKCU\Software\Classes\V83.COMConnector` → CLSID `{181e893d-73a4-4722-b61d-d604b3d67d47}`
- `HKCU\Software\Classes\CLSID\{181e893d-...}\InprocServer32` → путь к `comcntr.dll`, ThreadingModel=Both

### 2. TYPE_E_LIBNOTREGISTERED (0x8002801D) при Connect()
Класс зарегистрирован, но библиотека типов — нет; без неё позднее связывание не находит `Connect`.
**Решение:** зарегистрировать typelib `{98ac3b5b-5323-418f-8f07-e32f231d2393}` v1.0:
`HKCU\Software\Classes\TypeLib\{...}\1.0\0\win64` → путь к comcntr.dll (+ FLAGS, HELPDIR).
Проверка: `HKCR\TypeLib\{98AC3B5B-5323-418F-8F07-E32F231D2393}` существует.

### 3. У COM-соединения НЕТ метода Execute / CreateObject
В 8.3 `Выполнить`/`Вычислить` — операторы языка, а не методы COM. Есть только
`NewObject`, `Метаданные`, `ВнешниеОбработки`, `XMLСтрока`, `ПользователиИнформационнойБазы`.
**Решение:** произвольный код исполняется через внешнюю обработку-исполнитель
(`build/mcpExecutor.epf`, функции `ВыполнитьКод(Код)`/`ВычислитьВыражение(Выражение)`),
загружаемую через `conn.ВнешниеОбработки.Создать(path)`. Код пишет результат в переменную `Результат`.

### 4. Глобальные объекты недоступны по имени во внешнем соединении
`СистемнаяИнформация` и подобные → «Переменная не определена».
**Решение:** создавать через конструктор: `СИ = Новый СистемнаяИнформация;`.

### 5. «Предупреждение безопасности» при загрузке EPF (в COM — ошибка 1001)
Платформа блокирует загрузку обработки, если у пользователя ИБ включена
«Защита от опасных действий» (по умолчанию ВКЛ).
**Решение (вручную, один раз):** Конфигуратор → Администрирование → Пользователи →
<пользователь> → вкладка «Прочие» → снять «Защита от опасных действий».
Через COM флаг read-only, в ibcmd команд нет, в Users.xml не сериализуется (issue xUnitFor1C#700).

### 6. Пользователь ИБ не создаётся «с нуля»
`ПользователиИнформационнойБазы.Записать()` → «не осталось бы ни одного пользователя
с административными правами». Создание первого пользователя требует роли с админ-правами.
`Users.xml` при загрузке конфигурации ИГНОРИРУЕТСЯ (пользователи не часть конфига!).
**Решение:** роль «ПолныеПрава» в конфигурации (Configuration.xml + Roles/ПолныеПрава,
все права Configuration.*, включая Administration) + создание через COM:
`u = users.СоздатьПользователя(); u.Имя="Администратор"; u.Пароль="";
u.Роли.Добавить(conn.Метаданные.Роли.ПолныеПрава); u.Записать()`.
Записать — метод ОБЪЕКТА пользователя, не коллекции.

### 7. COM-объекты привязаны к потоку (апартаменту)
Нельзя передавать COM-объекты между потоками — всё через один поток с CoInitialize
(ThreadPoolExecutor(max_workers=1) + pythoncom.CoInitialize в initializer).

### 8. V83.Application оставляет процессы `1cv8.exe -Embedding`
Автоматизация толстого клиента вешает сессии, и монопольная операция (`/UpdateDBCfg`) падает
с «Ошибка исключительной блокировки информационной базы».

**Как освобождать базу — по ситуации, и это важно не перепутать:**

- **Своя машина, свои процессы.** Убивать можно только свои: сначала посмотреть, что это
  за процесс и когда запущен (`Get-Process 1cv8* | Select-Object Id, StartTime, Path`),
  и завершать конкретный `Id`, а не всё по маске.
- **Общий терминальный сервер или чужая база — НИКОГДА не убивать процессы по маске.**
  `Get-Process 1cv8* | Stop-Process -Force` там выкидывает живых разработчиков из
  конфигуратора и теряет их несохранённую работу: это ровно тот случай, когда «починил себе»
  означает «сломал другим». Правильный путь — завершить **свой** сеанс в 1С (консоль кластера
  или «Активные пользователи»), дождаться окна и попросить администратора, если база занята
  чужими сеансами.
- **Перед монопольной операцией** проверять, свободна ли база (лог исключительной блокировки
  прямо скажет, что кто-то сидит), и планировать такие операции на согласованное время.

## Конфигурация (XML, DESIGNER)

### 9. Версия формата: 8.3.18 = 2.11
meta-compile/скилы генерируют 2.17+ (8.3.24+). Для старых платформ менять
`version="2.x"` → `version="2.11"` во всех XML. Лестница: 8.3.20→2.13, 8.3.23→2.16, 8.3.24→2.17.

### 10. DESIGNER: «Пользователь ИБ не идентифицирован»
После появления пользователей DESIGNER требует аутентификацию. Пустой пароль передавать
СЛИТНО: `/N"Администратор" /P""` (с пробелом `/P ""` не работает).

### 11. Сборка выгрузки: не забыть Languages/ и Roles/
Configuration.xml ссылается на Language.Русский и Role.ПолныеПрава — их файлы должны
лежать рядом (Languages/, Roles/). При копировании из генератора легко потерять.

### 12. ChildObjects: порядок типов фиксирован
Language → Role → Enum → Catalog → Document → AccumulationRegister (по спец.
1c-configuration-spec.md §2.4), внутри типа — по алфавиту.

### 13. Реквизиты/измерения/ресурсы — inline в ChildObjects
meta-compile пишет дочерние объекты inline (с uuid внутри файла объекта) — платформа
8.3.18 принимает такой формат при LoadConfigFromFiles.

### 14. Документы и регистры: связь через `<RegisterRecords>` в документе
У регистра файл Ext/Documents.xml не обязателен — связь восстанавливается из документов.

## Python / Windows

### 15. Кракозябры в выводе
Запускать: `$env:PYTHONIOENCODING="utf-8"; python -X utf8 script.py`.

### 16. Кавычки в аргументах python через PowerShell
PowerShell съедает/искажает кавычки в аргументах командной строки — для кода 1С с
кавычками использовать файлы-скрипты, а не inline-аргументы.

### 17. Raw-строки Python с `\"`
`r'...Pwd=\"\"'` — бэкслеши попадают в строку соединения. Использовать f-строки:
`f'File="{path}";Usr="Администратор";Pwd=""'`.

### 18. OLE-даты с годом 9999 → OSError [Errno 22]
`pywintypes.Time(datetime(9999,12,31))` при передаче в `УстановитьПараметр` падает.
**Решение:** использовать 2099-12-31 как «бесконечную» дату в запросах.

### 19. ibcmd 8.3.18 — урезанный синтаксис
Нет `infobase info`, `config export` без `--out`, нет команд пользователей. Выгрузка XML —
через `1cv8 DESIGNER /DumpConfigToFiles`, загрузка — `/LoadConfigFromFiles /UpdateDBCfg`.

### 20. EPF из XML: формат версии для старой платформы
При сборке EPF корневой XML имеет `version="2.11"` для 8.3.18 (2.17 не примется).

## Регистрация / окружение

### 21. Python: нужен pywin32
`pip install pywin32` (win32com.client, pythoncom, pywintypes).

### 22. Консольная кодировка PowerShell
UTF-8 текст от 1С в консоли может отображаться кракозябрами — это косметика;
данные в файлах корректны.

### 23. У ссылки нет метода Удалить
`Выборка.Ссылка.Удалить()` → «Метод объекта не обнаружен (Удалить)».
**Решение:** `Выборка.Ссылка.ПолучитьОбъект().Удалить()`.

### 24. Для Каждого по выборке в Выполнить() может падать
«Итератор для значения не определен» в контексте обработки-исполнителя.
**Решение:** `Пока Выборка.Следующий() Цикл ... КонецЦикла;` вместо `Для Каждого`.

### 25. Удаление проведённых документов
Проведённый документ удаляется вместе с движениями регистров через `ПолучитьОбъект().Удалить()`
(движения снимаются автоматически). Справочник с движениями удалять только после документов.

## Расширения конфигурации (CFE) — рабочий приём

### 26. Расширение с обработкой-исполнителем работает при ВКЛЮЧЁННОЙ «Защите от опасных действий»
ВАЖНО для боевых баз: обработка-исполнитель, добавленная в базу как объект
**расширения конфигурации** (DataProcessor в CFE), доступна во внешнем соединении и исполняет
код у пользователя с ВКЛЮЧЁННОЙ защитой. Внешний EPF платформа при этом блокирует —
то есть защита продолжает работать, ослаблять её не нужно и не требуется. Расширение
доставляется администратором один раз штатной операцией `LoadConfigFromFiles` + `UpdateDBCfg`
(обычный способ сопровождения конфигурации), а объём доступного коду определяется ролью,
назначенной пользователю ИБ.

Создание: `cfe-init` (формат и совместимость определяются из выгрузки базовой конфигурации),
объект — `meta-compile` `{"type": "DataProcessor", "name": "<Префикс>_ИсполнительКода"}` +
модуль ВыполнитьКод/ВычислитьВыражение, регистрация в ChildObjects расширения.
Применение к базе (8.3.18): два шага, параметр СЛИТНО:
```
1cv8 DESIGNER /F "base" /N"Администратор" /P"" /LoadConfigFromFiles "ext_dir" -Extension"Имя" /Out l.log /DisableStartupDialogs
1cv8 DESIGNER /F "base" /N"Администратор" /P"" /UpdateDBCfg -Extension"Имя" /Out l.log /DisableStartupDialogs
```
`-Extension "Имя"` раздельно — «Ошибка в параметрах командной строки».

### 27. COM-методы обработок из конфигурации возвращают кортеж
Вызов `ВыполнитьКод("...")` у обработки из расширения через COM возвращает кортеж
`(результат, код)` (у EPF — просто значение). Нормализовать: `if tuple len==2 and [1] is str: take [0]`.

### 28. Менеджер Обработки не индексируется через []
`conn.Обработки["Имя"]` в pywin32 не работает — только `getattr(conn.Обработки, "Имя")`.

### 29. Пользователь, созданный через COM, имеет защиту ВКЛ по умолчанию
`СоздатьПользователя()` → «Защита от опасных действий» = Истина (read-only через COM).
Удобный тест-объект: показывает, что расширение исполняет код при штатной (не ослабленной)
настройке защиты — то есть работоспособность не зависит от снятия защиты.

## Устойчивость моста

### 30. Сетевые обрывы/рестарты кластера
COM-вызовы падают с pywintypes.com_error. Мост `bridge/onec.py` имеет `_with_retry`:
сброс соединения/исполнителя + повтор (retries=1, задержка 0.6–1.2 с). Бизнес-ошибки 1С
(например «Поле не найдено») тоже проходят через retry — это приемлемый оверхед, зато
обрывы переживаются прозрачно. `execute(code, timeout=...)` ограничивает время вызова.

### 31. См. запись № 27
Кортежи от COM-методов обработок из конфигурации — запись № 27; нормализация в `OneC._norm`.

## Серверный режим (кластер, СУБД)

### 33. Создание серверной ИБ 1С через командную строку (8.3.18)
`1cv8 CREATEINFOBASE Srvr=...;Ref=...` для серверной базы НЕ работает («Неверные или отсутствующие
параметры соединения»). Работает низкоуровневый COM-путь:
```python
wp = connector.ConnectWorkingProcess("localhost:1560")   # rphost, порт из консоли кластера
info = wp.CreateInfoBaseInfo()                           # Name, DBMS, DBServerName, DBName, DBUser, DBPassword, Locale
wp.CreateInfoBase(info, True)                            # True = создать БД в СУБД
```
DESIGNER для серверной базы: `/S"host\ref"` (НЕ `Srvr=...;Ref=...`).

### 34. mchar: 1С 8.3.18 требует расширение PostgreSQL mchar
Обычный PostgreSQL его не имеет (ошибка `could not open extension control file mchar.control`).
Есть в Postgres Pro 1C (или сборка из исходников). При этом установка Postgres Pro через apt
опасна для машин с другими PostgreSQL: apt удаляет штатные пакеты и маскирует службу —
подробности во внутренних заметках о среде, а вывод общий: на общих машинах PG Pro через apt
не ставить, брать tar.gz или договариваться.

## Python/MCP

### 35. Ставить пакеты Python в venv, а не в системный Python (часть записи)
`pip install mcp` в системный Python падает: `'...\Scripts\cffi-gen-src.exe' -> '...deleteme'`
(нет прав на каталог Scripts). **Решение:** venv — `python -m venv .venv`, ставить в него.
Частности нашей рабочей машины (путь к системному Python) — во внутренних заметках о среде.

### 36. mcp 2.x переименовал FastMCP в MCPServer
`from mcp.server.fastmcp import FastMCP` в mcp>=2.0 падает с подсказкой миграции.
**Решение:** `pip install "mcp<2"` (v1, как в проверенном mcp-1c-com).

### 37. MCP-сервер: строка соединения по умолчанию должна включать пользователя
Если строить `File="..."` без Usr — «Идентификация пользователя не выполнена».
**Решение:** дефолт `Usr="Администратор";Pwd=""` (как в onec.BASE), переопределяется env.

## Хранилище конфигурации (Configuration Repository)

### 38. Создание рабочей базы из хранилища в batch (8.3.18)
- `CREATEINFOBASE File=... /ConfigurationRepositoryF ...` создаёт ПУСТУЮ базу, конфигурацию НЕ загружает;
- `BindCfg` принимает ТОЛЬКО пустую базу («Конфигурация не пустая!» для непустой);
- `ConfigurationRepositoryGet` в batch ЗАВИСАЕТ (вероятно, ждёт интерактивного подтверждения).
**Рабочий рецепт:** хранилище создаётся из базы-донора `ConfigurationRepositoryCreate` — база-донор
САМА становится рабочей базой под хранилищем (её НЕ отвязывать!). Для второй базы — создать пустую и
связать ДО загрузки конфигурации, либо использовать GUI «создать ИБ из хранилища».

### 39. Один пользователь хранилища — одна ИБ
При bind второй базы тем же пользователем: «у пользователя имеется другая ИБ, связанная с хранилищем».
**Решение:** `/ConfigurationRepositoryAddUser` для второго пользователя, либо отвязать первую базу
(`/ConfigurationRepositoryUnbindCfg`).

### 40. Команды хранилища требуют двойную аутентификацию
`/N"..." /P"..."` (пользователь ИБ) + `/ConfigurationRepositoryF"путь" /ConfigurationRepositoryN"пользователь" /ConfigurationRepositoryP"пароль"` (хранилище) — всегда.

### 41. /ConfigurationRepositoryLock со списком в batch захватывает все объекты
Лог показывает «Объект захвачен: ...» для ВСЕХ объектов, даже при указании `Catalog.Товары`.
Если нужно точечно — использовать точные русские имена или мириться (для демо ок).

### 42. Цикл «захват → изменение → помещение» в batch (проверено)
```
1. /ConfigurationRepositoryLock <объекты>          # захват
2. /DumpConfigToFiles <dir>                        # выгрузка XML (с параметрами хранилища)
3. правка XML (реквизиты/модули/формы)
4. /LoadConfigFromFiles <dir> -listFile <список> -partial -updateConfigDumpInfo -Format 2.11
5. /UpdateDBCfg                                    # применить к БД
6. /ConfigurationRepositoryCommit /ConfigurationRepositoryComment "текст"
```
Частичная загрузка (-partial) — только по захваченным объектам; полная в связанную базу невозможна.

## PowerShell-мост (без Python)

### 43. PS 5.1: COM-объект из ФУНКЦИИ теряет диспетчеризацию
Если COM-объект возвращён из функции PowerShell (return), `InvokeMember` на нём даёт
`DISP_E_UNKNOWNNAME` даже для имён, которые работали инлайн. `PSObject.BaseObject` не спасает.
**Решение:** ВСЕ COM-цепочки в `onec.ps1` писать инлайн (без функций-обёрток). Это проверено:
инлайн `Обработки → ИИМост_ИсполнительКода → Создать → ВыполнитьКод` работает на PS 5.1.

### 44. .ps1-файлы обязаны быть UTF-8 с BOM
PS 5.1 читает .ps1 без BOM как ANSI (cp1251) — кириллица в строках и именах методов 1С
превращается в кракозябры и парсер падает. **Решение:** сохранять с BOM
(`[System.IO.File]::WriteAllText($p, $c, (New-Object System.Text.UTF8Encoding($true)))`).

Три уточнения, полученные на практике:

- **BOM теряется при правке файлов инструментами** (в т.ч. патчами и редакторами) — правка
  одного комментария в `.ps1` способна уронить рабочий скрипт. Проверять после каждой правки:
  `powershell -NoProfile -File tools\check_ps_bom.ps1` (ключ `-Fix` добавляет BOM, где нет).
- **Симптом потери BOM коварен:** скрипт «вроде тот же», но падает с `Unexpected token` на
  первой русской строке, а в тексте ошибки видна мешанина вида `Р—Р°РїСѓСЃС‚РёС‚Рµ`.
- **Скрипт-лечилка сам подвержен этой же болезни:** сохранив `check_ps_bom.ps1` без BOM,
  получаешь файл, который не запускается именно потому, что должен чинить. Лечение —
  добавить BOM снаружи (одной командой из консоли), после чего скрипт работает сам.
  Заодно `$PSScriptRoot` в блоке `param()` в PS 5.1 пуст — путь к корню считать в теле скрипта.

### 45. Сборка и применение расширения (.cfe)
- Выгрузка расширения в файл: `1cv8 DESIGNER /F "база" /N /P /DumpCfg"файл.cfe" -Extension"Имя"`.
- Применение: `/LoadCfg"файл.cfe" -Extension"Имя"` + `/UpdateDBCfg -Extension"Имя"` (монопольный режим).
- .cfe — стандартный формат, переносится между машинами/версиями платформы.

### 46. Заимствованный Language в расширении конфликтует при применении к другой базе
Расширение, содержащее заимствованный `Language.Русский` (создаётся cfe-init scaffold), при
применении к базе с ДРУГИМ uuid языка падает: «Значение контролируемого свойства
ОбъектРасширяемойКонфигурации ... не совпадает». **Решение:** удалить из расширения
`Languages/Русский.xml`, строку `<Language>Русский</Language>` из ChildObjects и
`<DefaultLanguage>` из Properties. Проверено: применяется к любой базе.

### 47. PS 5.1: Start-Process/& ломают аргументы 1cv8 с кавычками/кириллицей
`& exe` может не заполнить `$LASTEXITCODE`; `Start-Process -ArgumentList` искажает кавычки
(exit 1 при успешном логе). **Решение:** `System.Diagnostics.ProcessStartInfo` +
`Arguments = (массив) -join ' '` (элементы уже содержат кавычки) + `WaitForExit()` +
`ExitCode`. Проверено на apply_extension.ps1.

**Тот же эффект при вызове чужих программ (проверено на `tools/ssh_exec.py`):**
`python tools\ssh_exec.py --cs 'Srvr="srv";Ref="база";Usr="имя";Pwd=""'` доходит до Python
**без кавычек** — PowerShell 5.1 съедает их при передаче аргумента нативной программе,
и строка соединения становится нерабочей (внешне похоже на «неверные параметры соединения»).
**Обход:** передавать строку соединения через переменную окружения (`ONEC_CONNECTION_STRING`),
а не аргументом; значения из переменных окружения PowerShell не искажает. В `ssh_exec.py`
на это добавлено предупреждение: если в строке есть `=`, но нет ни одной кавычки — скрипт
пишет подсказку в stderr.

## Удалённый режим (SSH)

### 48. Кириллица в аргументах через SSH-оболочку Windows ломается
`ssh host "powershell -File onec.ps1 ... 'ВЫБРАТЬ ...'"` — кодировка аргументов искажается
(SSH-оболочка Windows + cmd + powershell). **Решение:** `-EncodedCommand` —
команда собирается в строку, кодируется base64 UTF-16LE и передаётся одним токеном:
`ssh host "powershell -NoProfile -EncodedCommand <b64>"`.
Проверено: exec/query с кириллицей доезжают корректно.

### 49. Windows OpenSSH: права на authorized_keys
Если ssh отказывает по ключу — файл `%USERPROFILE%\.ssh\authorized_keys` должен иметь
права только владельца + SYSTEM + Administrators, без наследования:
`icacls authorized_keys /inheritance:r /grant:r "user:F" "SYSTEM:F" "Administrators:F"`.
Для членов группы Administrators используется `C:\ProgramData\ssh\administrators_authorized_keys`
(вторая строка `AuthorizedKeysFile` в `sshd_config`).

## Регистр бухгалтерии (практика)

### 51. Запись движения регистра бухгалтерии
- У записи регистра бухгалтерии с корреспонденцией ресурс — **СуммаДт / СуммаКт** (не «Сумма»!).
  Поля «Сумма» нет — «Поле объекта не обнаружено (Сумма)».
- **Период обязателен**: «Период не может быть пустым!» — задавать `Дв.Период = Дата;`.
- ВидДвижения у бухгалтерии НЕТ (это у регистров накопления) — корреспонденция задаётся СчетДт/СчетКт.
- Регистраторы обязательны: у регистра `Ext/Documents.xml` + в `RegisterRecords` документов,
  иначе «Ни один из документов не является регистратором».

### 52. Ограничения глобального контекста внешнего соединения
- `ДАТАВРЕМЯ(...)` (встроенный язык) — НЕ определена во внешнем соединении;
  `Новый Дата(...)` — «не могут создаваться значения примитивных типов».
  **Решение:** не использовать; период в виртуальные таблицы — через параметры-даты из ТекущаяДата()
  или считать по фактической таблице (без периода). `ТекущаяДата()` работает.
- Предопределённые счета плана счетов адресуются **по имени без иерархии**:
  `ПланыСчетов.Хозрасчетный.Выручка` (не `...Продажи.Выручка`) — «Поле объекта не обнаружено (Выручка)».

## Сопровождение самого инструмента

### 53. Исходники C#-моста были утеряны при уборке рабочей папки
Собраны `bridge/bin_fd/*` оставались, а `src/onec-cs/Program.cs` пропал вместе с черновиками.
**Решение:** восстановлен декомпиляцией из самой сборки —
`dotnet tool install ilspycmd --tool-path <папка>`, затем
`ilspycmd -o <вывод> bridge/bin_fd/onec-cs.dll`; код вычищен, собирается
`dotnet publish src/onec-cs -c Release -o bridge/bin_fd` (framework-dependent, ~162 КБ)
или с `-r win-x64 -p:SelfContained=true -p:PublishSingleFile=true` (самодостаточный, ~70 МБ).
**Вывод на будущее:** бинарник в репозитории всегда сопровождается исходником в `src/`;
перед уборкой папок проверять, что исходники закоммичены.
Полезная деталь: `dotnet`-тулзы ставятся в отдельную папку (`--tool-path`) — машину не засоряем.

### 54. Дефолтные значения с личными путями в коде
`bridge/onec.py` содержал `_BASE_PATH = r"C:\Users\<...>\InfoBase"`, `tools/exttest.py` — те же пути,
`.v8-project.json` — путь и пользователя рабочей машины.
**Решение:** дефолт берётся из окружения (`ONEC_CONNECTION_STRING` / `ONEC_FILE` / `ONEC_USR` / `ONEC_PWD`),
при пустой строке — понятная ошибка; локальный `.v8-project.json` убран в `.gitignore`,
в репозиторий положен шаблон `.v8-project.json.example`.

### 55. MCP-клиент не пробрасывает переменные окружения в сервер
Симптом: `bridge/mcp_server.py` запускается, инструменты видны, но подключение падает с
`File="";Usr="Администратор";Pwd=""` — «Неверные или отсутствующие параметры соединения».
Причина: SDK `mcp` (`stdio_client`) при `StdioServerParameters` без `env` передаёт дочернему
процессу **урезанное** окружение (PATH/HOME и т.п.), а не окружение родителя; `ONEC_CONNECTION_STRING`
до сервера не доходит.
**Решение:** указывать строку соединения в `env` конфигурации MCP-клиента (`.mcp.json`),
а при запуске тестов — передавать `env=dict(os.environ)` в `StdioServerParameters`.
Сервер при этом исправен — это особенность запуска, а не моста.

### 56. Массовая уборка папок: проверять приёмник ДО удаления источника
При переносе дублей (`Copy-Item`/`Move-Item` по вычисленным путям) часть файлов оказалась
совсем не там, где ожидалось: заметили это только потому, что сверили **содержимое приёмника**
перед удалением источника. Если бы удалили сразу — потеряли бы декомпилированный исходник
`cluster.py` и скрипты-зонды.
**Правила, которые из этого следуют:**
- после копирования/перемещения печатать `Get-ChildItem` приёмника и считать файлы
  (`Measure-Object`) — до любого `Remove-Item`;
- для больших деревьев с длинными путями — `robocopy /E` (он же `/MOVE`), а не `Move-Item`
  (на глубоких `.git`-путях `Move-Item` падает с «The parameter is incorrect»);
- `Copy-Item` молча **сливает** содержимое в существующую папку: если в приёмнике был свой
  `tools/`, сравнение наборов файлов покажет «лишние» — это не ошибка копирования, а следы
  длинных путей (`.git`), которые `Get-ChildItem -Recurse` не перечислил;
- удалять дубли из рабочей папки только после архивации уникального в `.internal/`
  (там сейчас лежит `from-infobase/`: старые `src`, `tools`, `srv` и заметки).

### 57. PowerShell: имена переменных регистронезависимы — `$d` и `$D` это ОДНА переменная
Разгадка той самой «мистики», когда файлы уезжали не туда, куда указывал путь:
в скрипте были `$I`, `$P`, `$D`, а внутри — цикл `foreach ($d in @("src","tools","cc-1c-skills")) { $p = Join-Path $I $d; ... }`.
Поскольку `$d`/`$D` и `$p`/`$P` — одно и то же, цикл **затёр** и путь-приёмник `$D`, и корень `$P`
последним значением (`InfoBase\cc-1c-skills`). Дальше `Copy-Item -Destination $D` честно
скопировал всё в репозиторий навыков — ошибки не было, ошибка была в именах переменных.

Правила:

- не использовать имена, отличающиеся только регистром (`$p`/`$P`, `$d`/`$D`, `$i`/`$I`, `$a`/`$A`);
  для вложенных циклов брать осмысленные имена (`$dir`, `$root`, `$destPath`);
- перед `Remove-Item` проверять, что переменная пути всё ещё та, что задумана
  (`Write-Host $destPath`) — цена проверки одна строка;
- тот же принцип в других языках оболочки не работает: `bash`/`sh` регистр различают,
  поэтому привычка из bash молча ломается именно в PowerShell.
