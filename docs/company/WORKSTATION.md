### 32. Установка postgrespro-1c-XX УДАЛЯЕТ штатные пакеты PostgreSQL и маскирует postgresql.service
Произошло на нашей машине при попытке поставить PG Pro для расширения `mchar`:
- apt при конфликте **удаляет все штатные пакеты** `postgresql-13/14/16/17`, `postgresql-common`;
- postinst **маскирует** `postgresql.service`;
- данные кластеров сохраняются, но их нечем запускать (бинарии удалены).

Восстановление:
```bash
sudo apt-get remove --purge -y postgrespro-1c-13*
sudo apt-get install -y postgresql-16 postgresql-17 postgresql-common
sudo pg_ctlcluster 16 main start
```
Вывод: на общих машинах PG Pro через apt **не ставить** — брать tar.gz или договариваться.
Общее требование платформы к `mchar` — в `docs/core/PITFALLS.md`, запись 34.

### 35. Системный pip на нашей машине не может ставить пакеты с exe-скриптами (часть записи)
Системный Python стоит в `C:\Python311`, каталог `C:\Python311\Scripts` недоступен на запись:
`pip install mcp` падает с `'C:\Python311\Scripts\cffi-gen-src.exe' -> '...deleteme'` (WinError 2).
**Решение:** ставим зависимости в venv проекта (`python -m venv .venv`) — общий вывод в записи 35
файла `docs/core/PITFALLS.md`.

## Стенд для проверки моста (локальная учебная база)

На локальной машине живёт маленькая учебная база — она нужна **только как полигон**,
где разрешено то, что запрещено на стенде заказчика: запись, движения регистров,
применение расширений, свободный `exec`, эксперименты с C#-мостом.

Зачем она нужна:

- это единственное место, где можно проверить изменение моста, расширения или обработки-
  исполнителя, **не трогая базу заказчика**;
- она же позволяет любому, кто клонирует репозиторий, убедиться, что мост работает
  end-to-end (`check` → исполнитель отвечает, запросы идут), не имея своей базы 1С.

Чем она **не** является: ни демонстрацией, ни образцом, ни приближением к реальной
конфигурации. Настоящая проверка — MVP на тестовой базе заказчика; игрушка не показывает
ни объёмов, ни легаси, ни поведения на больших данных.
