# VM агента: где живёт разбор конфигурации

> **Документ внутренний.** Входит в репозиторий №2 («репозиторий компании»).

Машина выделяется специально под агента, чтобы **не трогать общий терминальный сервер**, на
котором работают люди (`WORKSTATION.md`). Разбор конфигурации — самая тяжёлая операция агента,
и она выполняется здесь: не на машине разработчика и не на стороне харнеса.

## Роли машин

| Машина | Что на ней | Чего на ней нет |
|---|---|---|
| **VM агента** (эта) | платформа 1С, мост, разбор контейнеров, снимки кода | харнес |
| Терминальный сервер (общий) | люди, их работа | наши операции — не ходим без отдельной причины |
| Харнес (Linux) | агент, харнес, веб-интерфейс | 1С и тяжёлых разборов здесь нет |

Разбор большой конфигурации на стороне харнеса **не делается**: у харнеса мало памяти, и это
не его работа. Харнес только отдаёт узкие запросы и получает один модуль за раз.

## Тулчейн на VM

Ставится без прав администратора: Python + venv, внутрь — `v8unpack` (MIT) через `pip`.
Свой парсер контейнеров **не пишем** — см. `SPEC-code-snapshot.md` и `PITFALLS.md` №60.

Проверено 2026-09-15 на артефактах из репозитория: разбор `.epf` и `.cfe` даёт исходный код
модулей, совпадающий с исходниками в репозитории **байт-в-байт**. Команды и детали — в отчёте PoC
(`1c-unpack-poc.md` в рабочей папке агента).

## Раскладка каталогов

```
C:\1c-work\
  cf\      два поколения контейнеров (.cf): текущее и предыдущее — чтобы diff был возможен всегда
  temp\    временная распаковка; удаляется по завершении задачи
  state\   инвентарь объектов, хэши, сводки diff
```

Точные имена, лимиты и набор стадий — в конфиге конвейера (`SPEC-code-snapshot.md`).

## Правила

- **Временную распаковку не храним.** Долговременное состояние — это `state\` на VM и `map/`
  в репозитории.
- **Исходный код конфигурации не покидает VM.** В репозиторий уходят инвентарь, карта и сводки
  diff — никогда `.bsl` конфигурации.
- **Защищённые модули вендора не читаем и не декомпилируем.** Не потому что «нельзя», а потому
  что не нужно.
- **Захват объектов в хранилище не используем.** Выгрузка конфигурацию не изменяет, поэтому
  лок не нужен; `/ConfigurationRepositoryLock` в batch берёт всё дерево (грабля №41) и
  останавливает работу программистов. Цикл «захват → правка → коммит» — отдельная тема и позже.
- **Секреты живут только здесь**, в файле, исключённом из git. Строка соединения не попадает ни
  в репозиторий, ни в аргументы командной строки (иначе видна в списке процессов), ни в карту.
  См. `ACCESS.md`.
