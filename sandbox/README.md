# sandbox — полигон для проверки моста

Здесь лежит маленькая учебная конфигурация, на которой отлаживался мост. Это **не продукт,
не демонстрация и не образец**: настоящая проверка делается на тестовой базе заказчика.

Зачем полигон нужен:

- он единственное место, где разрешено то, что запрещено на рабочем стенде: запись,
  проведение документов, движения регистров, применение расширений, свободный `exec`;
- любая правка `bridge/`, обработки-исполнителя или C#-моста проверяется здесь,
  **не трогая базу заказчика**;
- человек, впервые клонировавший репозиторий, может убедиться, что мост работает
  end-to-end, не имея своей базы 1С.

Чем полигон **не** является: он не показывает ни объёмов реальных данных, ни легаси,
ни поведения на больших таблицах — то есть ровно того, ради чего делается MVP.

## Что внутри

```
api.py             # HTTP-обёртка над мостом (пример прикладного слоя)
src/cfg/           # конфигурация-полигон: справочники, документы, регистры накопления
src/cfg_buh/       # та же конфигурация с бухгалтерией (план счетов, регистр бухгалтерии)
src/basecfg/       # базовая конфигурация с ролью ПолныеПрава и пользователем
src/cfg_gen/       # JSON-описания для генерации объектов мета-компилятором
tools/seed.py      # наполнение данными
tools/repost.py    # перепроведение документов
tools/otchet.py    # отчёты по остаткам и продажам
tools/buh_itog2.py # итоги по бухгалтерии
tools/check.py     # проверка остатков и финансовых итогов
tools/exttest.py   # проверка: расширение работает при включённой «Защите от опасных действий»
tools/mcp_test.py  # проверка MCP-инструментов (в т.ч. ушедших бизнес-операций)
```

## Как воссоздать полигон

1. Создать пустую файловую базу и загрузить в неё конфигурацию из `src/cfg_buh`
   (или `src/cfg`) — см. команды `1cv8 DESIGNER` в `README.md` репозитория.
2. Применить расширение-исполнитель: `apply_extension.ps1 -InfoBasePath <путь>`.
3. Наполнить данными: `python -X utf8 sandbox/tools/seed.py`.
4. Проверить: `python -X utf8 bridge/onec.py check` → должен ответить исполнитель и запросы.

## Правило

Всё, что относится к полигону, живёт здесь и **не попадает** в продуктовую часть:
в `bridge/`, `src/executor`, `src/cfe`, `src/onec-cs` и в `docs/core/`. Так фасад
репозитория остаётся про мост, а не про игрушечный магазин.
